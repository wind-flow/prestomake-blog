GitHub Pages는 정적 파일을 무료로 공개하기 좋은 선택지입니다. 다만 “어떤 브랜치를 공개할 것인가”와 “빌드를 어디에서 할 것인가”를 구분해야 설정이 단순해집니다.

## 브랜치에서 바로 배포하기

완성된 HTML, CSS, 이미지가 특정 브랜치에 들어 있다면 Pages가 그 브랜치의 루트나 `docs` 폴더를 바로 공개할 수 있습니다. 구조가 단순하고 결과물을 눈으로 확인하기 쉽습니다. 대신 Astro 같은 빌드 도구를 쓰면 로컬이나 별도 자동화에서 결과물을 만들어 해당 브랜치에 올려야 합니다.

## Actions로 빌드하고 배포하기

원본 코드를 기본 브랜치에 올리면 GitHub Actions가 의존성을 설치하고 빌드한 뒤 결과물을 Pages에 배포합니다. 팀원이 여러 명이거나 발행이 잦다면 반복 작업을 줄일 수 있습니다. 반면 실행 환경의 Node 버전, 패키지 잠금 파일과 권한 설정을 정확히 관리해야 합니다.

## 프로젝트 페이지의 기본 경로

사용자 페이지는 보통 `계정.github.io` 루트에 배포되지만, 프로젝트 페이지는 `계정.github.io/저장소명/` 아래에 배포됩니다. 사이트 생성기의 `base` 설정이 저장소명과 다르면 CSS나 이미지 주소가 루트를 가리켜 화면이 깨질 수 있습니다.

커스텀 도메인을 연결하면 보통 기본 경로를 `/`로 바꿉니다. 이때 canonical URL, RSS, 사이트맵과 내부 링크도 새 도메인을 기준으로 생성되는지 함께 확인합니다.

## 배포 직후 확인하기

1. 홈과 개별 글이 모두 HTTP 200으로 열리는지 확인합니다.
2. 새로고침해도 CSS와 이미지가 유지되는지 봅니다.
3. 존재하지 않는 주소에서 404 페이지가 표시되는지 확인합니다.
4. `robots.txt`, 사이트맵과 RSS 주소를 직접 엽니다.
5. 페이지 소스에서 canonical URL이 실제 공개 주소와 같은지 확인합니다.

배포 성공 표시만으로는 충분하지 않습니다. 브라우저에서 실제 공개 주소를 기준으로 링크와 메타데이터까지 확인해야 검색엔진과 방문자에게 같은 결과가 전달됩니다.
