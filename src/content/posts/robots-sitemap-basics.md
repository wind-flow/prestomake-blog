`robots.txt`와 사이트맵은 모두 검색 로봇과 관련 있지만 목적이 다릅니다. 하나를 설정했다고 다른 하나의 역할까지 해결되는 것은 아닙니다.

## robots.txt는 접근 지침이다

`robots.txt`는 사이트의 루트에 놓이며 크롤러가 어느 경로를 요청해도 되는지 안내합니다. 공개 블로그라면 일반적으로 전체 접근을 허용하고 사이트맵 주소를 함께 적습니다.

중요한 점은 이 파일이 보안 장치가 아니라는 것입니다. 비공개 문서 주소를 차단 목록에 적으면 오히려 경로가 공개될 수 있습니다. 인증이 필요한 내용은 로그인과 접근 권한으로 보호해야 합니다.

## 사이트맵은 발견 목록이다

사이트맵은 검색엔진이 찾았으면 하는 대표 URL을 제공합니다. 모든 URL의 색인을 보장하지는 않지만 새 사이트나 내부 링크가 적은 페이지를 발견하는 데 도움을 줍니다.

초안, 검색 결과, 중복 주소와 오류 페이지는 사이트맵에서 제외합니다. 각 URL은 실제로 200 응답을 반환하고 자신의 canonical URL을 가리켜야 합니다. 커스텀 도메인으로 바꾼 뒤 예전 호스팅 주소가 남지 않았는지도 확인합니다.

## noindex는 색인 지침이다

검색 결과에 표시하지 않을 페이지는 HTML의 robots 메타 태그나 HTTP 헤더에서 `noindex`를 사용합니다. 그런데 `robots.txt`에서 해당 페이지의 접근까지 막으면 크롤러가 `noindex`를 읽지 못할 수 있습니다. 접근 허용과 검색 노출 여부를 별개의 결정으로 다뤄야 하는 이유입니다.

## 배포 후 검증 순서

1. 브라우저에서 `/robots.txt`를 직접 엽니다.
2. 그 안의 사이트맵 URL을 따라갑니다.
3. 사이트맵의 URL 표본을 열어 200 응답을 확인합니다.
4. 페이지 소스의 canonical URL과 robots 메타를 봅니다.
5. 검색 도구에 사이트맵을 제출하고 읽기 오류를 확인합니다.

정적 사이트에서는 빌드 도구가 사이트맵을 자동 생성할 수 있습니다. 그래도 기본 URL 설정이 잘못되면 잘못된 주소가 정확하게 대량 생성됩니다. 자동 생성 여부보다 공개 결과를 검사하는 습관이 중요합니다.
