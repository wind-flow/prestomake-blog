도메인 연결은 DNS 레코드를 저장하는 순간 끝나지 않습니다. 이름이 올바른 서버를 가리키고, 호스팅 서비스가 도메인을 소유한 사이트에 연결하며, HTTPS 인증서가 준비되어야 방문자가 안전하게 접속할 수 있습니다.

## 변경 전에 기록할 것

현재 네임서버와 DNS 레코드를 내보내거나 화면으로 남깁니다. 웹사이트와 관계없는 MX, TXT 레코드가 메일과 서비스 인증에 사용될 수 있기 때문입니다. 도메인 등록 기관 계정의 복구 수단과 만료일도 확인합니다.

## DNS와 호스팅을 함께 맞춘다

DNS에는 호스팅 서비스가 안내한 값만 입력합니다. 루트 도메인과 `www`를 모두 사용할 경우 두 주소의 목적지를 정하고, 대표가 아닌 주소는 대표 주소로 이동하도록 구성합니다.

DNS 조회 결과만으로는 충분하지 않습니다. 호스팅 서비스의 커스텀 도메인 상태가 승인됐는지 확인해야 합니다. 다른 사용자의 프로젝트에 도메인이 잘못 연결되는 것을 막기 위해 소유권 검증이 필요할 수 있습니다.

## HTTPS가 준비될 때까지

DNS가 먼저 전파되고 인증서 발급은 조금 늦게 끝날 수 있습니다. 인증서가 아직 없을 때 HTTPS 강제를 서둘러 켜면 오류가 보일 수 있습니다. 호스팅 화면에서 인증서 상태가 정상인지 확인한 후 HTTP 요청이 HTTPS로 이동하는지 시험합니다.

## 대표 주소가 남아 있는 곳

- 페이지의 canonical URL
- Open Graph와 공유 이미지 주소
- RSS 피드 링크
- `robots.txt` 안의 사이트맵 주소
- 사이트맵에 포함된 개별 페이지 주소
- 분석 도구와 검색 도구의 속성

사이트 코드의 기본 URL을 한 곳에서 관리하면 누락을 줄일 수 있습니다. 변경 후 생성된 HTML 소스에서 실제 값을 다시 확인합니다.

## 외부에서 마지막 확인

로컬 네트워크의 DNS 캐시만 보지 말고 권한 있는 네임서버와 공용 DNS 결과도 확인합니다. 시크릿 창에서 루트, `www`, HTTP와 HTTPS 네 조합을 열어 최종 도착 주소가 하나인지 봅니다. 마지막으로 홈, 글, 정책 페이지와 존재하지 않는 주소의 응답 상태를 기록합니다.

문제가 생기면 한꺼번에 설정을 바꾸지 말고 DNS, 호스팅 도메인 상태, 인증서 순서로 원인을 분리하세요. [DNS 레코드의 역할](/posts/custom-domain-dns/)을 함께 보면 각 단계의 책임 범위를 구분하기 쉽습니다.
