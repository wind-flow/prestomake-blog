정적 사이트와 워드프레스 중 무엇이 더 좋은지를 묻기보다, 누가 어떤 방식으로 운영할지를 먼저 물어야 합니다. 두 방식 모두 블로그를 만들 수 있지만 콘텐츠가 공개되는 과정과 유지보수의 성격이 다릅니다.

## 정적 사이트가 잘 맞는 경우

정적 사이트는 글과 템플릿을 미리 HTML로 만들어 배포합니다. 방문 요청마다 데이터베이스에서 페이지를 조립하지 않으므로 구조가 단순하고 캐시하기 쉽습니다. 글을 Markdown으로 관리하고 Git으로 변경 이력을 남기고 싶다면 특히 잘 맞습니다.

반면 브라우저 관리자 화면에서 바로 글을 쓰는 경험은 기본 제공되지 않습니다. 작성자가 Git과 빌드 과정을 불편해한다면 별도 편집 도구나 자동화가 필요합니다. 댓글, 회원가입과 결제도 외부 서비스나 별도 서버로 구성해야 합니다.

## 워드프레스가 잘 맞는 경우

워드프레스는 관리자 화면에서 글, 이미지, 메뉴를 관리할 수 있습니다. 여러 작성자가 역할을 나눠 발행하거나 플러그인으로 기능을 빠르게 추가해야 할 때 편리합니다. 비개발자가 수시로 수정하는 사이트라면 편집 경험이 큰 장점입니다.

대신 코어, 테마와 플러그인을 꾸준히 업데이트해야 합니다. 플러그인이 늘수록 서로 충돌하거나 성능에 영향을 줄 가능성도 커집니다. 데이터베이스와 업로드 파일을 함께 백업해야 하며 로그인 화면의 보안도 관리 대상입니다.

## 네 가지 질문으로 결정하기

1. 글을 쓰는 사람이 Git을 사용할 수 있는가?
2. 로그인이나 실시간 데이터처럼 서버 기능이 필요한가?
3. 업데이트와 보안 점검을 누가 담당하는가?
4. 문제가 생겼을 때 이전 버전으로 되돌리는 절차가 있는가?

글 중심의 작은 사이트이고 코드 기반 운영에 익숙하다면 정적 사이트가 단순합니다. 여러 작성자와 동적 기능이 핵심이라면 워드프레스가 시간을 아껴줄 수 있습니다. 방문자 수보다 편집자와 운영자의 작업 흐름을 기준으로 고르는 것이 오래가는 선택입니다.
