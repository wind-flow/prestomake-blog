광고 심사는 코드 한 줄이 보인다고 끝나지 않습니다. 방문자가 읽을 만한 고유 콘텐츠가 있고, 원하는 정보를 찾을 수 있으며, 사이트 운영 주체와 데이터 사용 방식을 이해할 수 있어야 합니다. 승인 자체를 보장하는 공식적인 글 개수나 글자 수는 없으므로 숫자만 채우는 접근은 피해야 합니다.

## 콘텐츠 표본을 직접 읽는다

최신 글만 보지 말고 대표 주제별로 여러 편을 고릅니다. 각 글이 하나의 질문에 답하는지, 일반적인 설명을 넘어 실제 선택 기준과 확인 방법을 제공하는지 봅니다. 비슷한 제목과 문단 구조를 반복한 글은 합치거나 서로 다른 목적을 분명히 합니다.

외부 자료를 이용했다면 그대로 바꿔 쓰는 데 그치지 않고 직접 검증, 비교, 해석을 더해야 합니다. 이미지와 인용의 사용 권한도 확인합니다.

## 방문자의 이동을 시험한다

처음 방문한 사람의 입장에서 홈에서 글을 찾고, 관련 글로 이동하고, 다시 전체 목록으로 돌아가 봅니다. 모바일 메뉴, 검색, 태그와 404 페이지도 확인합니다. 빈 카테고리나 준비 중 페이지만 공개되어 있으면 제거합니다.

## 운영 투명성을 확인한다

소개 페이지에는 사이트의 목적, 다루는 범위와 편집 기준을 적습니다. 문의 가능한 실제 경로를 제공하고 개인정보처리방침에서 쿠키와 제3자 광고 서비스 사용 가능성을 설명합니다. 광고나 제휴가 글의 판단에 영향을 주지 않는다는 원칙도 고지합니다.

## 기술 항목을 확인한다

- 공개 도메인이 HTTPS로 정상 접속되는가
- 광고 코드가 `<head>` 안에 정확히 한 번 들어가는가
- `ads.txt`가 루트에서 올바른 게시자 ID를 반환하는가
- `robots.txt`가 광고 및 검색 크롤러를 막지 않는가
- canonical URL과 사이트맵이 실제 도메인을 사용하는가
- 주요 페이지가 로그인 없이 열리는가

## 광고보다 본문이 우선이다

콘텐츠가 거의 없는 검색, 태그와 오류 화면에 광고를 과도하게 노출하지 않습니다. 본문을 가리거나 광고 클릭을 유도하는 표현도 사용하지 않습니다. 광고와 이미지가 서로 관련된 콘텐츠처럼 오해되지 않게 배치합니다.

마지막으로 주요 페이지를 시크릿 창에서 열고 링크, 모바일 화면과 로딩을 확인합니다. 심사 요청 후에는 사이트를 삭제해 다시 제출하기보다 상태를 유지하면서 안내된 문제를 수정하는 편이 좋습니다. 자체 점검의 목표는 심사만 통과하는 것이 아니라 광고가 붙은 뒤에도 신뢰할 수 있는 사이트를 운영하는 것입니다.
