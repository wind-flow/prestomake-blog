도메인을 샀다고 웹사이트가 자동으로 연결되지는 않습니다. DNS는 방문자가 입력한 이름을 실제 호스팅 위치로 안내합니다. 연결 오류를 줄이려면 레코드의 역할과 변경 순서를 구분해야 합니다.

## 루트 도메인과 하위 도메인

`example.com`은 루트 또는 apex 도메인이고, `www.example.com`은 하위 도메인입니다. GitHub Pages에서 루트 도메인은 안내된 IP 주소를 가리키는 A·AAAA 레코드를 사용하고, `www`는 대상 호스트를 가리키는 CNAME을 사용하는 구성이 일반적입니다.

DNS 제공업체에 따라 루트에서도 별칭 기능을 제공하지만 이름은 ALIAS, ANAME 또는 CNAME flattening처럼 다를 수 있습니다. 제공업체 설명을 확인한 뒤 설정해야 합니다.

## 기존 레코드를 먼저 기록하기

변경 전 현재 DNS 레코드를 캡처하거나 내보냅니다. 특히 MX와 TXT 레코드는 메일 수신, 발신 인증이나 서비스 소유권 확인에 사용될 수 있습니다. 웹사이트를 연결하면서 관련 없는 레코드를 삭제하면 메일이 중단될 수 있습니다.

## 안전한 연결 순서

1. 호스팅 서비스에서 요구하는 도메인과 DNS 값을 확인합니다.
2. 기존 레코드를 백업합니다.
3. 충돌하는 웹 레코드만 수정합니다.
4. 호스팅 서비스에 커스텀 도메인을 등록합니다.
5. DNS 조회 결과와 실제 HTTPS 접속을 각각 확인합니다.
6. 인증서 발급이 끝난 뒤 HTTPS 강제를 활성화합니다.

DNS 변경은 각 캐시의 유효 시간이 끝날 때까지 서로 다른 결과가 보일 수 있습니다. 이때 설정을 반복해서 바꾸기보다 권한 있는 네임서버의 응답과 호스팅 서비스의 검증 상태를 구분해서 확인하는 편이 안전합니다.

## 연결 후 놓치기 쉬운 항목

홈이 열려도 사이트맵과 RSS가 예전 GitHub 주소를 가리킬 수 있습니다. 사이트 설정의 기본 URL, canonical URL, Open Graph 이미지와 `robots.txt`를 새 도메인 기준으로 다시 빌드합니다. `www`와 루트 가운데 대표 주소도 하나로 정하고 다른 주소는 대표 주소로 이동시킵니다.
